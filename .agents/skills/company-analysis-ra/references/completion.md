# 조사 완료와 최종 보고서

## 조사 범위

기본 `research.profile=standard`의 필수 범위는 기업·사업, 3대 재무제표, 밸류에이션, 컨센서스, 산업·경쟁, 공시·일정, 결론·반증 조건이다. 사용자가 사업·재무 중심으로 범위를 정하면 fundamentals를 사용한다. 이때도 사업·재무·산업·공시·결론은 필수다. 이미 선택한 범위의 자료가 없다는 이유로 profile을 바꾸지 않는다. 기술지표·수급·파생은 요청과 분석 필요성에 따라 보충하며 적용 여부와 한계를 기록한다.

비금융업은 최근 완료 3개 연도의 필수 계정 외에 매출원가·총이익·판관비·세전이익·법인세, 유동/비유동 자산·부채, 매출채권·재고, 투자/재무 CF, 영업이익률·FCF·순차입금을 확보한다. period·basis·scope·단위가 같은 관측치를 쓴다. 실제 미적용 계정에는 not-applicable과 원문 근거·사유를 둔다. 최신 공개 분기/누적의 매출·영업이익도 필요하며 실제/잠정을 외부 전망과 구분한다.

금융업은 financialModel=financial과 financialRows로 업종 계정·라벨을 지정한다. 일반 CFO/FCF 대신 이자/보험서비스/수수료 손익, 자산 구성, 자본·건전성 등 실제 사업에 맞는 지표를 선택한다. 추가한 업종 계정은 세 완료 연도에 확보하거나 실제 미적용의 이유를 기록한다. 신용비용·CSM·자본비율을 업종이 다른 회사끼리 동일 지표로 비교하지 않는다.

## 수집이 막혔을 때

누락을 찾으면 먼저 같은 발행자의 원문 경로를 바꿔 확인한다. 공시는 본문/첨부/PDF·정정본·IR 재게시, 시세는 거래소/기업 IR 연결 시세의 주식 종류와 시각, 하우스 자료는 해당 리서치 게시판/원문 PDF를 확인한다. 자료 제공사의 접근 가능한 화면에서는 원출처·정의·기준일을 확인하고 secondary로 기록한다. 기사 재전재만으로 최신 하우스 원문이나 독립적인 복수 근거를 만들지 않는다.

같은 실패 요청을 반복하지 않고 다른 발행자 원문이나 공식 경로로 진행한다. 필요한 자료가 유료·인증·권한에 막혀 대체 원문도 없다면 URL·실패/불일치 이유를 attempts에 남긴다. 외부 접근 제한을 우회하거나 날짜·가격·기관명을 만들어 넣지 않는다. 수집하지 않은 항목을 '자료 없음'으로 단정하지 않는다.

`coverage`는 business/financials/valuation/consensus/industry/events/conclusion/technical/flows 중 각 topic을 한 번씩 기록한다. done은 실제 수집한 sourceIds 또는 observationIds와 분석 본문이 있어야 한다. unavailable에는 접근 시도가 필수다. 필수 항목의 not-applicable에는 원문 근거가 필요하다. 선택적 미확보는 범위 표에 남기고 필수 범위 완료와 구분한다.

## 분석과 문서

executive는 핵심 변화·주요 동인·양면 쟁점·다음 확인 조건을 회사별로 요약한다. narrative는 원자료를 읽어 주는 데 그치지 않고 사업부·가격/물량/믹스·현금전환·일회성 항목을 연결한다. debates에는 근거 있는 긍정·부정 해석을 함께 둔다. 실제 외부 반대 의견이 없으면 에이전트 해석과 반증 조건으로 구분하며 하우스에 귀속하지 않는다.

valuation에는 실제/예상 이익·순자산 분모, 가격 기준시각, 외부 제공/직접 산출, 비교 업종·기간 차이를 설명한다. 배수의 원자료는 observations, 숫자는 토큰으로 참조한다. EPS/BPS는 원/주, PER/PBR은 배 등 단위가 총액과 섞이지 않게 쓴다. 음수·0 분모는 N/A와 사유를 쓰고 적정가·투자 제언으로 바꾸지 않는다.

리서치 표·현금흐름·이익률·사업부 구분은 [presentation.md](presentation.md)를 따른다. 추가 금융업 계정은 financialRows의 statement/metric/label/style/afterMetric으로 배치한다. 기본 계정의 라벨도 바꿀 수 있지만 관측치 정의를 바꾸지는 않는다. 그림·뉴스 개수를 맞추려고 자료를 만들지 않는다.

## 검수 기록과 실행

1. intent=draft로 실제 입력·범위·접근 시도를 저장하고 audit로 누락을 확인한다. 모든 checks는 미실행이면 not-run이다.
2. 원문의 사용 버전, 첫 통화 열, 부호, 필수/상세 계정·주가·하우스 귀속을 대조한다. 숫자 대조 목록은 계산 결과가 아닌 모든 원자료 observationIds, 문서 확인 목록은 모든 사용 sourceIds다. 일부만 보았다면 원문 검수를 완료로 표시하지 않는다.
3. build 후 데스크톱·모바일의 첫 화면, 세 재무표, 최근 분기, 차트, 결측 표시, 출처 번호 이동과 원본 링크를 확인한다. 화면 이미지와 확인 기록을 작업 폴더에 보존한다. 사용자 출력이 print-ready면 실제 A4/PDF 페이지 분할도 확인한다.
4. audit가 표시한 evidenceSha256과 rendererSha256을 해당 검수 당시 checks에 저장한다. 입력/분석 문장·범위가 바뀌면 원문·화면 기록을 갱신한다. 생성기가 바뀌면 화면을 다시 확인한다. sources에는 evidenceSha256, 화면/인쇄에는 두 지문을 모두 연결한다. reviewedAt는 실제 검수시각이다.
5. intent=final로 바꾸고 build→verify→audit --final을 실행한다. intent는 지문에 포함되지 않아 최종 제출 전환 자체가 검수를 무효화하지 않는다. FINAL은 실제로 수행한 검수 기록을 입력했다는 전제의 판정이며 외부 원문 자동 인증이 아니다.

HTML 모드의 필수 검수는 sources·desktop·mobile다. print-ready는 print도 필요하다. `reviewedAt=null`, 원문/숫자 대조 누락, 지문 불일치, 필수 조사 누락, 입력·출력 오류가 있으면 최종 판정을 받지 못한다. 가상 fixture는 항상 DRAFT/PARTIAL이다. 예제 안의 가상 검수 기록은 입력 구조·테스트용이고 실제 검수 증거가 아니다.

## 산출물과 상태

HTML은 차트 코드·CSS·데이터를 포함하며 생성 후 CDN 접속이 필요 없다. 원본 링크를 열거나 새로운 자료를 수집할 때는 인터넷이 필요하다. 처음 npm ci를 수행할 때도 레지스트리 접근이 필요하다.

| 항목 | 의미 |
| --- | --- |
| gate.status | PASS/PARTIAL/FAIL: 자동 데이터 계약·계산·생성 검사 |
| gate.research.state | FINAL/DRAFT/UNASSESSED: 정한 조사 범위와 검수 기록의 충족 여부 |
| audit 종료 0 | 일반 audit 완료, --final에서는 FINAL 충족 |
| audit 종료 1 | 입력·계산·생성 오류 |
| audit 종료 2 | --final 요청에서 미완료 상태 |

3.1 입력은 계속 생성·재검증하지만 UNASSESSED다. JSON·HTML·gate·원문 추출 및 화면 검수 기록을 함께 전달한다. 필수 범위의 외부 접근 제한이 남으면 DRAFT와 접근 시도·부족한 항목을 구체적으로 남긴다. 자동 PASS나 버전 번호를 조사 완료의 대용으로 사용하지 않는다.
